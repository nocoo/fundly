## 🔍 可即时执行的分析

以下 SQL 现在都能秒查：

```sql
-- 想找"某经理的所有基金"
SELECT b.fund_name FROM fund_manager_link l JOIN fund_basic_info b USING(fund_code)
WHERE l.manager_id='张坤' AND l.end_date IS NULL;

-- 想找"某股票的抱团基金"
SELECT b.fund_name, p.hold_pct FROM fund_portfolio p JOIN fund_basic_info b USING(fund_code)
WHERE p.stock_code='300308' AND p.report_date='2025-12-31'
ORDER BY p.hold_pct DESC LIMIT 20;

-- "低费率 + 高夏普"复合筛选
SELECT b.fund_name, f.mgmt_fee_pct, r.sharpe_1y
FROM fund_basic_info b
JOIN fund_fees f USING(fund_code) JOIN fund_risk_metrics r USING(fund_code)
WHERE b.fund_type LIKE '混合型-偏股' AND f.mgmt_fee_pct < 1.0 AND r.sharpe_1y > 2
ORDER BY r.sharpe_1y DESC LIMIT 20;
```

## 🚧 已知限制

1. **持仓仅最新一季**：`fetch:portfolio` 目前不带 `year/month` 参数，拿到东财默认返回的最新季（2025-Q4）。历史各季需要传参分季度重跑（未来 Phase 3）
2. **前 10 大重仓**：`topline=10` 上限，公募实际持仓多为几十只——不适合精确复制，适合风格/行业分析
3. **拆分事件为空**：fhsp 页面的拆分表几乎全是"暂无"，不是 parser 问题；确需拆分数据要单独拉基金公告
4. **经理去重仅按姓名**：`manager_id = name`。同名不同人（极少）会合并，将来若发现问题再引入 `company` 做联合键
5. **销售服务费**：目前提取 `null` 的多，因为 jjfl 页面对非 C 类基金不展示，属正常
6. **持仓 161 只失败**：全是 HTTP 514（东财"该基金无该季数据"），属**数据真空非故障**，不需要重试
7. **风险指标窗口 <30 样本**：全部返回 null（约 2,700 只新基金）
